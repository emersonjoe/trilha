# Spec 123 — O caminho até a API: a outra metade da régua

- **Issue**: [#94](https://github.com/emersonjoe/trilha/issues/94) — a issue é a fonte do
  escopo; a metade que mede a tela saiu na 0.71.0 (spec 090) e o comentário de lá registra,
  no próprio corpo da issue, o que ficou e por quê.
- **Branch**: `claude/relaxed-keller-v1pwuf`
- **Versão**: 0.102.0

## Por quê

A #94 pedia um cenário no `bench/agent` que medisse a Fase 7 inteira. A 0.71.0 entregou o
`port-listing`, que mede **a tela**: colunas, ordenação vinda da URL, paginação que preserva
o filtro, fragmento, nenhum JavaScript próprio. Ficou de fora, e a issue ficou aberta por
isso, a outra coisa que a issue pedia: **por onde a chamada saiu**.

É a parte que não cabia em nenhum dos cinco cenários porque nenhum deles tem um serviço de
pé durante a verificação. E é a parte onde a migração erra de um jeito que compila: a tela
em Next.js lia o token do `localStorage` e chamava a API do browser, então a porta ingênua é
uma página em Go que faz a mesma coisa com outro nome — um `fetch` numa ilha, ou um token
renderizado no HTML para o script achar. As duas passam em qualquer teste que olhe só a
página: a diferença aparece do **lado de lá**, no `Authorization` que chegou à API.

A régua não consegue ver isso de dentro do processo do app. Precisa de uma API de verdade
respondendo, e precisa perguntar a ela o que recebeu.

## O que muda

**`Scenario.Serve`** — um cenário pode subir o serviço com que o projeto conversa:

```go
// Serve brings up what the project talks to — a service that is somewhere
// else — and returns the environment saying where it landed, plus the way to
// take it down. Nil is a scenario that talks to nobody.
Serve func() (env []string, stop func())
```

Ele roda duas vezes: uma em volta do agente (`AgentOptions.Env`), para que o agente
experimente contra a API; outra em volta do `Verify`, que passa o mesmo endereço ao
`go test`. Uma instância por vez, e é a que respondeu ao teste escondido que ele lê.

**O cenário `api-call`**, sobre `examples/local-login` — o exemplo que já tem uma API que
não é dele. O `Prepare` devolve `app/painel/documentos/page.go` a um esqueleto, **apaga o
cliente gerado** (`internal/acervo`) e deixa o que uma migração de verdade tem na mão: a
página como era em React (`page.tsx.txt`, com `localStorage.getItem('api_token')` e o
`fetch`), a linha do `MIGRATION.md` e o `openapi.json` que a API publica.

O teste escondido lê a chamada do lado de lá:

- sem sessão não há tela **e não há chamada** — a API não fica sabendo que alguém tentou;
- a tela mostra nomes de arquivo que só a API tem, então ela chamou de verdade;
- o `Authorization` que **chegou** à API é o token da sessão de quem está logado;
- esse token **não aparece no HTML** — um token na página é o `localStorage` com outro nome;
- o `?q=` da URL chega à API como parâmetro, e não vira uma fatia filtrada em Go depois de
  pedir tudo;
- um `Authorization` mandado pelo browser **não** chega à API;
- nenhuma ilha e nenhum `<script src>` fora do kit.

E o `Check`, que é a metade da aceitação que pedido nenhum mostra: existe no projeto um
arquivo com o cabeçalho `Code generated by trilha client`. Uma chamada pode levar a
credencial certa e ainda ter sido escrita à mão sobre um documento que estava a um comando
de virar tipos. O outro caminho que a issue permite — `Config.Upstreams` — não é conferido
aqui porque este app **já declara um**: uma tela renderizada no servidor não passa pelo
proxy do próprio app, então o upstream do `setup.go` não diz nada sobre o que o agente fez.

**`examples/local-login` ganha a tela que é a resposta.** `/painel/documentos` lista o
acervo pelo cliente que o `trilha client` gera do `openapi.json` (commitado, como o
`trilha_gen.go`), com a credencial vindo da sessão pelo `context`. Sem `API_URL` a tela diz
o que falta, como o resto do exemplo. É ela que o `TestApiCallEhAtingivel` usa para provar
que a barra é atingível — sem isso um cenário pode medir uma barra que ninguém alcança, e
uma barra dessas não distingue um agente ruim de um teste impossível.

## Fora de escopo

- **Rodar a régua e publicar o número.** Cada execução chama um agente de verdade; o que a
  versão entrega é o cenário e a prova de que ele é uma régua válida. O `RESULTS.md` é
  regravado com a lista de cenários, não com medição nova.
- **O contador de "quantas vezes o agente abriu o `.tsx`"** que a issue cita: é medida de
  ferramenta, não de resultado, e o bench conta tokens e rodadas.
- **Um teste de que o cliente commitado do exemplo não envelheceu** quando o gerador muda.
  O `examples/cookbook/api` tem o mesmo buraco desde que existe; é uma issue própria, do
  `internal/client`, e não deste cenário.

## Constitution Check

| Princípio | Como respeita |
|---|---|
| II — só biblioteca padrão | O stub é `net/http/httptest`; o cliente gerado importa a biblioteca padrão e nada mais. O `bench` é módulo separado e continua sem dependências. |
| VI — teste primeiro | As duas provas antes do cenário valer: `TestFixturesFailWithoutTheAgent/api-call` (o teste escondido falha na fixture intocada, e não por não compilar) e `TestApiCallEhAtingivel` (passa contra a tela que o exemplo tem). Mais o stub e o `Check` com teste próprio. |
| VII — segurança por padrão | O que o cenário mede **é** a regra: a credencial sai da sessão, não do browser; o token não chega ao HTML; um `Authorization` de fora não é encaminhado. A tela do exemplo é a demonstração disso, e o teste de integração dela cobre os três. |

## Aceitação

- **SC-001** `go test ./...` no módulo `bench` passa, com `TestFixturesFailWithoutTheAgent`
  cobrindo seis cenários e `TestApiCallEhAtingivel` verde.
- **SC-002** `make bench-agent-dry` monta o `api-call` e a linha que ele imprime é
  `--- FAIL: TestBenchChamadaComACredencialDaSessao` — o teste escondido rodou e falhou, que
  é medição, e não "o fixture nem compila", que é régua quebrada.
- **SC-003** `go test ./examples/local-login/` prova, contra uma API falsa, que a chamada sai
  com o token da sessão, que o `?q=` chega à API, que o `Authorization` do browser não chega
  e que sem `API_URL` a tela explica em vez de quebrar.
- **SC-004** `api/current.txt` não muda: nada disto é superfície pública do framework.

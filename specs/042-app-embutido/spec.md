# Spec 042 — App embutido: pacote gerado, middleware por método e 4xx com a cara do app

- **Issues**: [#51](https://github.com/emersonjoe/trilha/issues/51),
  [#56](https://github.com/emersonjoe/trilha/issues/56) e
  [#53](https://github.com/emersonjoe/trilha/issues/53) — as issues são a fonte do escopo.
- **Branch**: `042-app-embutido`
- **Versão**: 0.32.0

## Por quê

As três vieram da mesma migração — o módulo de CRM do Farol, onze rotas dentro de um binário
`net/http` que já existe — e as três têm a mesma forma: a convenção resolve o caso do app que
**é** o programa e deixa sem lugar o app que **mora dentro** de um programa. Quando não há
lugar, a regra desce para dentro do handler, e um arquivo escrito à mão passa a guardar o que
o gerador deveria guardar. É o tipo de arquivo que envelhece calado: ninguém o quebra, ele só
para de estar certo no dia em que alguém cria uma pasta.

- **#51** — `trilha gen` escreve `package main` sempre. Um app embutido precisa ser um pacote
  comum para o servidor hospedeiro importar, então o autor copiou as onze chamadas de
  `a.Register(...)` para um `rotas.go` à mão. As onze viram cinquenta e três no roadmap do
  módulo, e `trilha gen --check` — que existe exatamente para pegar rota nova no CI — deixa de
  valer para o projeto inteiro.
- **#56** — `middleware.go` vale para a rota, não para o método. Numa pasta que serve um GET
  para quem lê o painel e um POST para quem edita funis, a permissão do POST desce para a
  primeira linha do handler. Nas outras dez rotas do módulo ela está em `middleware.go`; é a
  décima primeira que alguém vai esquecer de conferir.
- **#53** — `app/error.go` cobre 5xx e `app/not_found.go` cobre 404. O 403 — que num app com
  papéis é a resposta mais comum depois do 200 — sai numa página branca do framework, assinada
  "trilha", sem o menu nem o rodapé do painel. Seis rotas do CRM devolvem 403.

## O que muda

### 1. O pacote do arquivo gerado (#51)

`trilha gen` passa a **adotar o pacote que o diretório já declara**, que é o que a issue
esperava que acontecesse. A precedência, do mais explícito para o menos:

1. `trilha gen --package <nome>`, quando existe;
2. o pacote declarado pelos `.go` escritos à mão na raiz do app (ignorando `_test.go` e o
   próprio `trilha_gen.go`);
3. o pacote declarado por um `trilha_gen.go` que já esteja lá;
4. `main`.

O passo 3 é o que faz a bandeira valer uma vez só: quem começou com `--package crm` num
diretório ainda sem `.go` nenhum não precisa repeti-la no `trilha dev`, e **não precisa
repeti-la no `trilha gen --check` do CI** — o próprio arquivo gerado lembra a escolha.

Quando o pacote não é `main`, duas consequências e nada mais:

```go
// Code generated by trilha. DO NOT EDIT.
package crm

// NewApp builds the application. The host binary calls it and mounts a.Handler().
func NewApp() *trilha.App { ... }
// e nenhum func main()
```

O construtor é exportado (`NewApp`) porque quem chama mora em outro pacote; com `package main`
segue `newApp`, minúsculo, como hoje. `func main()` nunca é acrescentado fora do `package main`.

`trilha dev` e `trilha build` recusam um app assim com uma frase que diz o conserto — não há
binário para rodar, quem roda é o hospedeiro — em vez do erro de compilação do `go run`.

### 2. Middleware por método (#56)

O scanner reconhece em `middleware.go` os nomes por método, do mesmo jeito que já reconhece
`POST`/`DELETE` em `route.go`:

```go
// app/segmentos/middleware.go
func Middleware(c *trilha.Ctx, next trilha.Next) error     { ... } // toda a rota, como hoje
func MiddlewarePOST(c *trilha.Ctx, next trilha.Next) error { ... } // só o POST
```

`GET`, `POST`, `PUT`, `PATCH` e `DELETE`. `Route` ganha
`MiddlewaresByMethod map[string][]MiddlewareFunc`, e a cadeia de um método é a cadeia da rota
seguida da cadeia do método:

```
Middleware herdados (de fora para dentro) → MiddlewareX herdados (de fora para dentro) → CSRF → handler
```

A herança é a mesma do `Middleware`: `MiddlewarePOST` em `app/middleware.go` guarda todo POST
da subárvore. Escolha deliberada — a alternativa (valer só para a rota do próprio arquivo)
faria um `MiddlewarePOST` numa pasta sem `page.go` virar código morto sem aviso, que é o
defeito que estas três issues descrevem.

`middleware.go` passa a ser válido com `Middleware`, com um `MiddlewareX`, ou com os dois. E um
`MiddlewareX` que não alcança nenhuma rota com aquele método na subárvore é **erro de scanner**
(`E_UNUSED_METHOD_MIDDLEWARE`), pela mesma razão: uma permissão que não guarda nada não pode
passar despercebida.

### 3. `error.go` recebe todo status de erro (#53)

Todo status que não é 404 passa a ir para `app/error.go`, com o layout do app, e não só os
5xx. O 404 continua em `app/not_found.go`. A assinatura não muda:

```go
func Error(c *trilha.Ctx, err error) (h.Node, error)
```

O status vem do erro, por uma função nova, exportada do que já existia em `statusOf`:

```go
// StatusOf classifies an error into the HTTP status the framework will send.
func trilha.StatusOf(err error) int
```

```go
func Error(c *trilha.Ctx, err error) (h.Node, error) {
	switch trilha.StatusOf(err) {
	case http.StatusForbidden:
		return painel.Negado(c), nil
	default:
		return painel.Erro(c), nil
	}
}
```

A página interna do framework (`simplePage`) continua como rede, com o texto de hoje, para
quando o app não define `error.go` ou quando o próprio `error.go` falha — que é como o 500 já
se comporta. Rota de API (`KindAPI`) segue em `application/problem+json`, intocada.

## Fora de escopo

- **Bandeira `--no-main` com `package main`** (#51). Sem pacote próprio ela só serve para um
  binário que declara `func main()` em outro arquivo, e para isso o scanner já tem o
  `rootHasMain`.
- **404 pelo `error.go`.** `not_found.go` existe e é o lugar; misturar os dois trocaria o
  endereço de uma convenção que está funcionando.
- **`app/denied.go`** (alternativa citada na #53). Um arquivo por status multiplica convenções;
  o `switch` no `error.go` que já existe resolve com o que a pessoa já sabe.
- **#52, #54, #55** — o resto da leva do Farol (cabeçalhos do hospedeiro, nome do cookie de
  CSRF, injeção de dependência). Mesma origem, escopos independentes.
